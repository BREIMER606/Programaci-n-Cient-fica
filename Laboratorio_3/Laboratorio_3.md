# LABORATORIO_3 — Multisensor Motion Analysis

This repository contains a structured, reproducible pipeline for preprocessing, visualization and analysis of a multisensor dataset (UWB, IMU accelerometer/gyroscope, pose, barometer). The main objective is to define global motion states from accelerometer data and evaluate a Random Forest classifier, using a clean project layout and reusable code modules.

## Data (`data/`)

All datasets are stored under `data/` and split into **raw** and **processed** subsets.

- `data/raw/`
  - Contains the original measurement file:
    - `const1-trial2-tdoa2.csv`: UWB TDOA measurements, IMU signals (accelerometer and gyroscope), pose estimates and barometric pressure recorded during a constrained motion experiment, in which a drone followed a predefined route and all measurements were collected from its onboard sensors.
- `data/processed/`
  - Contains the cleaned dataset generated by the preprocessing stage:
    - `const1-trial2-tdoa2_clean.csv`:
      - rows with missing values in `tdoa_meas` are removed  
      - only the columns required for this lab are kept (`t_pose`, `acc_x`, `acc_y`, `acc_z`)  
      - a moving-average filter is applied to the accelerometer channels (filtered versions may be added as extra columns)

All files are CSV with a header row. Time is given by `t_pose`. Raw files may contain `NaN` in non-critical sensors; the processed file enforces completeness for `tdoa_meas` but may still include missing values elsewhere.

## Source code (`Src/`)

The `Src/` directory holds all reusable modules, each implemented as a small library without hard-coded paths or print-based side effects.

### `Src/preprocessing/`

- Functions for:
  - loading CSV files into pandas DataFrames  
  - dropping rows with missing values in required columns  
  - selecting subsets of columns  
  - applying a moving-average filter to accelerometer signals using small OOP helper classes (`SensorSignal`, `OriginalSignal`, `FilteredSignal`)  
  - saving processed CSVs and comparison figures (original vs filtered)

### `Src/visualization/`

- High-level plotting utilities using `matplotlib` and `seaborn`:
  - correlation heatmap of selected numeric variables  
  - boxplot of physical variables  
  - violin plots showing distributions with quartiles  
- Each function receives:
  - a DataFrame
  - a list of columns to plot
  - an explicit output path for the PNG file

### `Src/analysis/`

Implements the main analysis workflow:

- **Integration acc → vel**  
  - `IntegratedSignal` class performs trapezoidal integration from acceleration to velocity for each axis.  
  - `generar_figura_integracion` produces a multi-panel figure comparing acceleration and integrated velocity.
- **Segment summary tables**  
  - `resumen_por_segmentos` and `guardar_resumen_segmentos_png` count total values, missing entries and percentage of missing data for sensor groups (`UWB`, `IMU_acc`, `IMU_gyro`, `Pose`) in both raw and processed datasets.
- **Global motion-state definition**  
  - `definir_clases_globales` computes the acceleration magnitude \(acc\_mod = \sqrt{acc_x^2 + acc_y^2 + acc_z^2}\) and uses two percentiles (by default 0.33 and 0.66) to define three balanced states: `repose`, `transition`, `motion`.  
  - `guardar_resumen_clases_png` saves the class distribution table.
- **Feature extraction (ACC)**  
  - `extract_imu_acc_features` computes mean, standard deviation, RMS, mean frequency and peak frequency for each accelerometer axis using FFT-based spectral analysis.  
  - `guardar_features_png` writes the feature table as a PNG with formatted values.
- **Random Forest classification**  
  - `entrenar_random_forest_acc` performs a stratified train/test split, trains a `RandomForestClassifier` on `acc_x`, `acc_y`, `acc_z` to predict `final_global_mobile_state`, and generates:
    - a classification report table (precision, recall, F1-score, support)
    - a confusion-matrix figure

## Results (`results/`)

All outputs produced by the pipeline are written under `results/`.

### `results/figures/`

- `heatmap_variables.png` – correlation heatmap.  
- `boxplot_variables.png` – boxplot of selected variables.  
- `violinplot_variables.png` – violin plots of distributions.  
- `integracion_acc.png` – acceleration and integrated velocity per accelerometer axis.  
- `rf_confusion.png` – confusion matrix of the Random Forest classifier.

### `results/tables/`

Each table is a PNG generated from a pandas DataFrame:

- `tabla_crudos.png` – total values, missing counts and %Missing per segment (raw data).  
- `tabla_procesados.png` – same metrics after preprocessing (processed data).  
- `tabla_features.png` – feature summary for accelerometer channels.  
- `tabla_clases.png` – distribution of motion classes (`repose`, `transition`, `motion`).  
- `rf_reporte.png` – classification report (precision, recall, F1-score, support, macro/weighted averages).

You can safely delete the contents of `results/`; they will be regenerated the next time the pipeline runs.

## How to run the pipeline

From the project root (`LABORATORIO_3/`), with the `LABORATORIO_3` environment activated:


The script executes:

1. **Preprocessing**
   - loads `data/raw/const1-trial2-tdoa2.csv`  
   - removes rows with missing `tdoa_meas`  
   - keeps `t_pose`, `acc_x`, `acc_y`, `acc_z`  
   - applies moving-average filters and saves `data/processed/const1-trial2-tdoa2_clean.csv`  
   - generates original vs filtered comparison figures for accelerometer channels
2. **Visualization**
   - creates heatmap, boxplot and violin plots for the available variables and saves them in `results/figures/`
3. **Analysis**
   - produces integration figures, raw/processed segment tables, motion-class definition and distribution table, feature table, Random Forest classification report and confusion matrix

## Reproducibility notes

- The environment is fully specified in `environment.yml` (Conda), enabling others to recreate the same software stack.  
- Random seeds (`random_state=42`) are fixed where relevant in the Random Forest to ensure stable train/test splits and metrics.  
- All outputs are generated programmatically from `Main.py` and stored under `results/`, so figures and tables can be reproduced at any time from the raw data.
