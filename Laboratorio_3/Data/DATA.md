# Data folder

This directory contains all datasets used in the project. Data are split between **raw** files (as obtained from the experiment) and **processed** files (cleaned and prefiltered for analysis).

## Structure

- `raw/`
  - Original measurement files as provided by the experiment.
  - In this lab, the main file is:
    - `const1-trial2-tdoa2.csv`: UWB TDOA measurements, IMU signals, Pose and barometer data recorded during a restricted motion test in which a drone followed a predefined route and all measurements were collected from its integrated sensors.

- `processed/`
  - Data files generated by the preprocessing stage of the pipeline (`Main.py`).
  - Current file:
    - `const1-trial2-tdoa2_clean.csv`: cleaned version of the raw dataset, after
      - removing rows with missing values in `tdoa_meas`,
      - keeping only the columns required for this lab (`t_pose`, `acc_x`, `acc_y`, `acc_z`),
      - applying a moving-average filter to the accelerometer channels.

## File format

All datasets are stored as **comma-separated values (CSV)** with a header row.

Main columns:

- `t_pose`: Time stamp of the pose estimate (used as reference time axis).
- `tdoa_meas`: UWB time-difference-of-arrival measurement (raw file only).
- `acc_x`, `acc_y`, `acc_z`: Linear acceleration components measured by the IMU.
- `gyro_x`, `gyro_y`, `gyro_z`: Angular velocity components (raw file only).
- `pose_x`, `pose_y`, `pose_z`: Estimated position coordinates (raw file only).
- `baro`: Barometric pressure (raw file only).

Missing values are encoded as empty cells / `NaN` in the raw data. The processed file removes rows with missing `tdoa_meas` but may still contain `NaN` in non-critical sensors.

## How the data are used

- `raw/const1-trial2-tdoa2.csv` is used only for:
  - reporting the amount of available data and missing values per sensor group (UWB, IMU_acc, IMU_gyro, Pose).
- `processed/const1-trial2-tdoa2_clean.csv` is the input for:
  - visualization (heatmaps, boxplots, violin plots),
  - definition of motion states (repose, transition, motion),
  - feature extraction from accelerometer signals,
  - Random Forest training and evaluation.

The preprocessing and analysis steps that generate the processed file and all results are implemented in `Src/preprocessing/processing.py`, `Src/analysis/analysis.py`, and orchestrated by `Main.py`.
